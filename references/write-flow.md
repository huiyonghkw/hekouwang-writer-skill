# WRITE 五步法 · 操作卡

> 适用：常规档及以上的写作/改文档请求。轻量档（改一句话/一个小表）免流程，直接改+一句说明。

## 五步

| 步 | 问题 | 产出 | 常见错误 |
|---|---|---|---|
| **W**ho 读者 | 写给谁？他拿它做什么？ | 一句话读者画像 + 用途（决策/执行/存档） | 不写读者就动笔，术语深浅全凭感觉 |
| **W**hy 目的 | 希望读者看完做什么？ | 结尾的呼吁动作（去办X、定Y、存Z） | 文档没有行动出口，读完不知道干嘛 |
| **H**ow 结构 | 用什么结构装内容？ | 标题骨架 + **每节一句核心句** | 先写正文后排结构，越写越散 |
| **D**raft 起草 | 填内容 | 表格优先的初稿；一句一事；数字加粗 | 大段 prose；一句话塞三个事实 |
| **P**olish 润色 | 删改 | 过检查清单后的终稿 | 只加不减——好文档是删出来的 |

## 每节核心句怎么写

每节标题下第一句就是结论，加粗。读者只读核心句就能跟上全文逻辑。

- 反例：`## 三、缴费记录`（下面自己看）
- 正例：`## 三、缴费记录\n\n**核心句：她的缴费家底已全部核实。12年已缴，仅2025年断缴，个人缴费合计1,600元。**`

## 七种文档原型结构

| 原型 | 结构 |
|---|---|
| 办事指南/家庭文档 | 摘要 →（可选：30秒导航）→ 已确认事实 → 规则 → 测算 → 时间线与行动清单（含失效条件）→ 依据 → 术语表 |
| 方案 | 背景 → 目标 → 方案 → 排期 → 资源 |
| 报告 | 结论 → 数据 → 分析 → 建议 |
| 说明 | 是什么 → 怎么做 → 注意事项 |
| 邮件 | 目的 → 背景 → 请求/行动 → 截止时间 |
| 汇报 | 结论 → 理由 → 行动（金字塔） |
| 修订 | 复述原意与改动点 → 出稿（保留事实，只调表达） |

## 单一真源（计划、日期、金额只完整写一处）

同一个计划/截止日/金额在多处完整重复，改一处漏一处，文档就自相矛盾。

- 完整版只写在一个地方：办事文档写在"时间线与行动清单"，测算写在测算节。
- 其他地方只写一行要点 + "见第X节"，不重复日期、操作路径、明细。
- 时间线和行动清单**合成一节**（勾选清单按时间分组），不要一节表格、一节清单各写一遍。
- 自检：随便挑一个截止日，全文搜它出现几次；超过 2 处（摘要一行 + 正文一处）就是重复。

## 摘要（最多 3 条）

| 条 | 回答什么 |
|---|---|
| 结论 | 现状 + 最终能得到什么（含"以核定为准"等模态） |
| 现在做什么 | 按时间的步骤，每步一行，细节指向正文 |
| 最大风险 | 出口闸门第二问的失效条件，一行 |

背景解释（"为什么查不到"）、算法、明细一律放正文，不进摘要。

## 30秒导航表（可选）

**只在两种情况下加**：正文超过 7 节；或者摘要回答不了读者最常问的问题。摘要已经写清"要做什么"、标题本身能当目录用时，不加——它会和摘要、标题重复。

要加时放在摘要后：

```markdown
## 我想干什么，去哪一节

| 你的问题 | 去这里 |
|---|---|
| …… | 第X节 |
```

## 措辞四原则

| 原则 | 做法 | 反例 → 正例 |
|---|---|---|
| 具体 | 用数字和事实 | "缴了不少年" → "缴了12年，合计1,600元" |
| 简洁 | 一句一意 | "既…又…而且…" → 拆两句 |
| 主动 | 动词+对象 | "对补缴进行了核定" → "窗口核定补缴档次" |
| 一致 | 全文术语统一 | "社保窗口/政务中心/经办窗口"混用 → 首次定义后只用一种 |

## 交付进度卡模板

```markdown
- 文档：[标题]   类型：[原型]   阶段：[初稿/修订/终稿]
- 结构完整度：▓▓▓▓▓░░░   数据完整度：▓▓▓░░░░░░（N 处待核实）
- 合规风险：🟢/🟡/🔴（非全绿时必须附：级别+位置+问题+改法）
- 本轮已完成：[…]   待完成：[…]
```

# 证据纪律 · 交付格式 · 降级与自进化

## 一、证据三分（每个结论标注属于哪类）

| 类 | 定义 | 文档中的标法 |
|---|---|---|
| 观察 | 有出处可查：文件、电话答复、官方原文 | "已核实"+ 出处（文件/日期） |
| 推断 | 从观察推出来：测算、估算 | "测算/约"+ 假设说明 |
| 未验证 | 没有依据或依据不足 | "待核实"/"暂无出处，建议核实" |

**纪律**：三者不混用。"约"不删（见句法纪律模态保护）；推断不当观察写；未验证不给确定结论。

## 一b、时效事实核查（什么时候查、查到哪里停）

**触发**：现行政策与执行口径、标准金额（基础养老金、补贴档次）、办理渠道与时间窗口、最新数据；或用户明确要求核实。常规常识、用户自己的业务事实不触发——用户事实以用户材料为准。

**步骤**：
1. 开查前先列本次要核的项目和每项需要的来源类型（法规政策 → 规范依据；地方正式文件 → 本地执行口径；官方发布/新闻 → 进展；电话答复 → 记日期和号码）。
2. 某项找到**能打开、信息齐全、无直接冲突**的官方原始来源 → 该项立即停，不为找"更新/更权威"的说法继续搜。
3. 打不开、缺必需信息或与另一来源直接冲突 → 围绕这个缺口补搜**一次**；不管结果如何都停，不换关键词、换站点循环搜。
4. 仍没补齐 → 标"暂无出处，建议核实"或"仅见于媒体报道，以窗口口径为准"，继续成稿。

**依据表纪律**：
- 列：文件/答复 · 关键内容 · 链接 · **访问日期**（电话答复写通话日期）。
- 链接逐字用实际打开的地址，不按标题或站点结构猜 URL；没打开过的页面不能写"已核实"。
- "已核实"至少要一个官方原始来源或有日期的电话答复；只有媒体转述 → 标"推断"或"待核实"。

## 一c、审稿意见分级（按性质，不按观感）

| 级别 | 性质 | 怎么写 |
|---|---|---|
| 🔴 已证实错误 | 与材料、规则、文内其他日期/数字明确矛盾 | 指出矛盾两处的位置 + 依据 + 直接给改法；不再要求用户"核实"已确认的输入 |
| 🟡 依据不足待核 | 材料不支持的事实或确定结论 | 指出缺什么依据；建议删掉无据断言或恢复原有程度（如加回"约""待核实"）；不写成"已证实相反" |
| 🟢 可选表达建议 | 不影响事实成立的措辞、结构、样式 | 有明确阅读收益才提，不列为必须修改 |

- 同一问题合并成一条；不为凑满三级而列正确内容。
- 用户只问"事实有没有错" → 只给 🔴🟡。范围内没问题 → 直说"未发现相应问题"。
- 不同主体、旧值与新值、合同总额与本次金额分别核对；两个数字不一致时，差额本身不能决定该改哪一个——回到来源判断。

## 二、出口闸门两问（交付前必答）

1. **最强反证**：这篇文档里哪个数字/结论最可能是错的？核实过了吗？——逼自己找出最脆弱的点，而不是平均用力。
2. **失效条件**：什么情况下它会过期（政策到期日、时间节点、电话答复换人）？写进文档了吗？
   - **写在哪**：行动清单旁边写完整版，摘要"最大风险"写一行。只出现在依据表里 = 没写（读者办事时不会翻依据表）。

答不上来 → 不许交付，回去补。

## 二b、修订的回退方式

修订铁律要求"可回退"，按这个顺序落实：

1. 文件在 git 里 → 靠 git，不另建备份。
2. 不在 git 里 → 交付的**改动清单**就是回退依据（位置 + 改前 → 改后），必须完整到能逐条手工还原。动笔前把原稿复制到系统临时目录，改完用 `scripts/change_list.py 原稿 改后稿` 对账，确认清单没有漏项。
3. 大改（重排结构、整篇重写）前可在同目录复制一份备份，并告诉用户文件名；是否保留由用户决定，不要假设备份一直在。

## 三、交付格式

```
1. 正文
2. 进度卡（结构/数据完整度、合规风险）
3. 需整改项：级别 + 位置（哪段哪句）+ 问题 + 怎么改
4. 放行项清单：超线未改的句子 + 放行理由
```

禁止：只报"合规风险🔴"不说位置；把部分完成写成全部完成。

**诚实状态标签**（照抄 dev-god 的纪律）：
- 改完了没验证 → 写"已修改，尚未验证"；
- 只过了构建/只跑了脚本 → 写"验证止于脚本扫描"；
- 外部阻塞 → 给已完成部分 + 缺失条件 + 可直接接续的下一步。

## 四、降级三件套（任何一步失败）

明确报告三件事：**哪一步失败 + 失败原因 + 用户可执行的下一步**。
不静默失败，不假装完成，不用"可能"糊弄。

例："分号密度检查未跑（脚本读取文件失败，文件含 BOM）。下一步：另存为 UTF-8 无 BOM 后重跑，或我改为内联读取。"

## 五、learnings 台账（自进化）

触发即记：用户纠正 / 自查发现错误 / 同一坑第二次 / 发现更好方法。

```markdown
## [LRN-YYYYMMDD-XXX] correction

**Logged**: 2026-10-15T10:00:00
**Priority**: medium
**Status**: pending
**Area**: docs

### Summary
一句话说错了什么、什么是对的

### Details
发生了什么、错在哪、正确的是什么

### Suggested Action
具体修复或防范动作

### Metadata
- Source: user_feedback | self_check | error
- Pattern-Key: 如 sentence.semicolon（可选，用于循环检测）
- Recurrence-Count: 1
- See Also: LRN-20251014-001（可选）
```

**晋升规则**：同一 Pattern-Key 的 Recurrence-Count ≥ 3，且跨 2 个任务、30 天内 → 蒸馏成一条短规则，晋升进 SKILL.md 的铁律/清单，并在 CHANGELOG.md 记一笔。

**记录纪律**：立即记、具体、含复现、关联文件、给具体修复建议；**不记录秘密、令牌、证件号**（案例要脱敏）。

# 术语表机制（一词一义的落地）

> 目的：同一概念全文一个叫法；跨文档也叫法一致。这是 doc_lint 同义词检查的数据源，
> 也是给领域文档（社保、财务、技术）复用的资产。

## 怎么用

1. **每进入一个新领域写第一篇文档**，先复制下方模板建 `glossary.md`（放文档同级或 skill 的 `assets/`），把该领域的核心概念登记：概念、标准叫法、别称（出现即算轮换）、一句话定义。
2. **写后续文档时**，把新概念追加进同一张表；文档中出现别称 → 换成标准叫法。
3. **机械检查**：`python3 scripts/doc_lint.py 文档.md --pairs "办理地点:社保窗口,政务中心,经办窗口"`。
   组多时可以写个 shell 循环把术语表里所有别称组喂进去（每组一个 `--pairs`）。
4. **人工放行三种合法情况**：定义行（"全文所称X，指……"）、引用原文（别的文件里的原词，加引号标明）、不同实体（市社保局和区城乡局是两个机构，不是同一概念的两种叫法）。

## 模板

```markdown
# 术语表 · [领域名]

| 概念 | 标准叫法 | 别称（出现即告警） | 一句话定义 |
|---|---|---|---|
| 例：补差业务 | 提档补差 | 升档补差、补差 | 把已缴年度补到更高档次，无补贴 |
| 例：办理地点 | 社保窗口 | 政务中心、经办窗口、便民服务中心 | 镇便民服务中心或区政务中心的社保窗口 |
```

## 与 references/style-rules.md 的关系

句法纪律里说"一词一义"是规则；本文件是让规则可执行的机制。没有术语表的检查只能覆盖内置的几个常见组；有术语表，检查就跟着领域长。

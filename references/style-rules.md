# 句法纪律 · 完整规则表

> 来源：asd-ste100（航空受控英语）迁移到中文 + 真笔翻译 STE-CN 映射的中文阈值。原则：**消除歧义，不是追求最短**。

## 规则表

| # | 规则 | 中文阈值/做法 | 机械检查 |
|---|---|---|---|
| 1 | 一句一事 | 分号连接两个事实 = 拆成两句 | doc_lint.py 分号密度 |
| 2 | 句长 | 单句 ≥45 字告警；≥60 字必拆 | sentence_load.py |
| 3 | 分句堆叠 | 句内逗号/分号 ≥5 → 改列表 | sentence_load.py |
| 4 | 修饰嵌套 | 句内「的」≥3 → 拆句 | sentence_load.py |
| 5 | 一词一义 | 同一概念全文一个叫法；轮换=缺陷 | doc_lint.py 同义词检查 |
| 6 | 枚举用列表 | 3 项以上并列 → 列表 | 人工 |
| 7 | 名词簇 | 不作硬性条数限制，超过 10 字的偏正短语考虑拆 | 人工 |
| 8 | 主动语态 | "窗口核定"优于"由窗口进行核定" | 人工 |
| 9 | 保留模态 | "可能/约/待核实"原样保留（见下） | 人工 |
| 10 | 不省略主语 | 省略造成指代不明时补回 | 人工 |

## 模态保护（最重要的单条）

**"可能"是内容，不是噪音。**

- "月养老金**约**668元" → 删"约"就是把测算说成核定，是**改变主张**，不是简化。
- "2027年保费**不能提前缴**（已确认）" → 括号里的确认状态是价值所在，删了读者无法判断可信度。
- 拆句时禁止用"此外/因此/由此可见"来连接——那是用加词代替断句。

## 放行项判定流程（长句不一定要拆）

```
句子超长？
 ├─ 是公式/等式（含 = ÷ + 链）        → 放行（拆开破坏可读性）
 ├─ 是 UI 操作路径（含 →）            → 放行（路径是硬信息）
 ├─ 是联系人/电话/证件号行            → 放行（字数是硬的）
 ├─ 是政策条款引用（含〔〕号/条/款）  → 放行（引用原文不改写）
 ├─ 是并列枚举（A、B、C 三项以上）    → 改列表，不必拆句
 └─ 以上都不是                        → 按语义边界拆；拆时不得增删信息
```

放行必须在心里（或交付说明里）给出理由，**不放任**。

## 同义词轮换的处理

1. doc_lint 报出轮换候选 → 人工判断是真轮换还是以下三种合法情况：
   - **定义行**（"全文所称X，指……"）——合法；
   - **引用原文**（别的文件/答复里的原词，如平昌指南的"升档补差"）——合法，可加引号标明；
   - **不同实体**（市社保局 vs 区城乡局是两个机构，不是同一概念的两种叫法）——合法。
2. 真轮换 → 选定一种叫法全文替换，并在术语表登记。

## 拆句操作规范

- 只做**重排与断句**：移动从句、改句号、改列表。
- 禁止：增删信息、加连接词、把两个事实合成一句更长的。
- 拆完对照原文数信息点：拆前几个事实，拆后还是几个。

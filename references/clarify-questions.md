# 动笔前的澄清问题清单

> 用户只说"帮我写个文档"时使用。纪律（借育儿大师的"最少输入原则"）：
> **能合理默认就默认，最多问 3 个；用户答得简短是常态，别连环追问。**
> 用户给了素材/附件（要求+材料至少两类）时，跳过收集，直接进结构。

## 通用五问（按序问，用户已说的别重复问）

| # | 问题 | 默认值（用户不说就用） |
|---|---|---|
| 1 | 写给谁看？ | "通用读者"——按此写术语表 |
| 2 | 拿它做什么用（决策/照着做/存档）？ | 照着做 |
| 3 | 要多长？ | 办事类 1-2 页；报告 2-3 页 |
| 4 | 什么时候要？ | 无硬时限 |
| 5 | 有参考范文或必须遵守的格式吗？ | 无 |

## 分文体补问（在通用五问之上）

| 文体 | 追加问题 |
|---|---|
| 办事指南/家庭文档 | 办事人是谁、去哪办、已经核实了哪些事实、哪些还没核实 |
| 方案 | 背景卡在哪、预算量级、谁批准 |
| 报告 | 给谁汇报、结论对方想先听什么 |
| 邮件 | 收件人角色、希望对方做什么、截止时间 |
| 修订（改已有文档） | **这篇要解决什么问题**（结构乱/数字错/太长/不像人话）——先问这个，别一上来就重写 |

## 模糊输入的三方向选择法

用户说"写得清楚点""顺一点"这类没目标的反馈时，一次给三个方向让他挑，禁止开放式追问：

> 你更想解决哪个：① 结构乱（读者找不到重点）② 句子难读（太长、太绕）③ 不像人话（AI 味）？

## 确认口径（信息收集完后）

一句话复述确认："读者是X，用来Y，篇幅Z，我先按这个写，默认项我列在这里。"未答项列出默认值，让用户有机会纠偏，但不阻塞动笔。

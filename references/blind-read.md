# 盲读：交稿前必过的一关

脚本查得出像不像 AI，查不出读者懂没懂。写的人知道每个数从哪来、每个词什么意思，自己读永远是通顺的。所以文章模式交稿前，必须找一个没看过素材、没参与写作的读者读一遍。

## 一、谁来读

- **首选**：开一个全新上下文的子 Agent（Cursor / Claude Code 的 Task、Codex 的新会话），只给它成稿和下面的提示词，不给研究包、策划单、对话历史。
- **宿主没有子 Agent**：把提示词和成稿交给作者，请作者在新会话里跑，或找一位真人读者。
- **不能自评代替**：写稿的同一个上下文回答这 8 个问题不算盲读。没跑盲读就在交付说明里写「未盲读」，不能写「已通过」。

## 二、读者画像

按选题挑一个，写进提示词。画像要具体到处境，不写「普通读者」。

| 选题类型 | 画像示例 |
|---|---|
| 民生、社保、办事 | 40 岁上下，在外地上班，正替老家父母办这件事；看得懂算术，不懂政策术语 |
| 财经、数据 | 关心这个行业但不做这行，手机上刷到这篇，读的时候会顺手打开计算器 |
| 技术 | 用过这个工具一两年，遇到过文中的坑但没弄懂原理 |

## 三、提示词模板

```text
你是一位读者：{画像}。你在手机上刷到下面这篇文章，从头读到尾。
你没看过任何背景材料，只能依据文章本身回答。请诚实，不要客气。

1. 读完你能用一句话复述这篇的核心判断吗？写出那句话。
2. 文中哪个数字或说法你第一次读没看懂、要回头重读？逐个指出。
3. 有没有哪个数你拿不准单位、时间段或会不会累加？（例如「这是一年的，还是每年都这样」）
4. 读完后你最想知道、但文章没给的那个数或那句话是什么？
5. 哪个术语或数字在解释之前就被用了？
6. 哪些提醒、免责或限定你读到第二遍就觉得啰嗦？各出现了几次？
7. 哪几句像官方文件、像套话或像故意写的金句？原句摘出来。
8. 读完你还会追问作者哪 3–5 个问题？

最后：如果只能改三处，你会改哪三处？
```

## 四、怎么用结果

1. **逐条归类**：每个问题落到一处改法，不笼统写「加强可读性」。

| 盲读发现 | 对应改法 |
|---|---|
| 复述不出核心判断 | 回 `article-writing.md` 第一节，重写那一句判断 |
| 数的单位、时间段、累加不清 | 按 `article-writing.md` 第一b节给数挂标签；标题和正文算法对齐 |
| 最想知道的数没给 | 补完整算例；素材没有就写明缺什么、去哪问 |
| 先用后讲 | 把解释挪到第一次使用之前 |
| 免责、口径啰嗦 | 按 `article-writing.md` 第四b节只留两处 |
| 像文件、套话、金句 | 按 `plain-talk.md` 改成人话；文号挪到来源 |
| 追问 | 逐个决定：本篇回答 / 留给下一期 / 写明为什么不答（如属于选档建议） |

2. **改完不必再盲读同一个读者**：第二轮如有必要，换一个新上下文，避免读者记住了上一版。
3. **交付说明里写清**：盲读画像、发现了几处、改了哪些、哪些没改及理由。追问清单原样附上，作者决定是否进下一期选题。

## 五、边界

- 盲读读者说「看不懂」是事实，说「应该改成 X」只是建议；改法仍守事实账和模态铁律，不为好懂改数字、删限定。
- 盲读不判断事实真假，事实核对仍靠来源和数字对账。

01 / 任务卡约束

成稿已有，要去套路、保事实。

场景

开源／付费终端主题包 README，读着像模板，分档信息重复。

你说

去 AI 味，中档；别改数字和付费边界；别编我没做过的经历。

借用

dbs-plain-writing 四块实测无冲突；行末去句号未借用。

02 / 诊断先列再改

句法之前，先数信息散落。

分档说明约 10 处散落：开头、badge、引用块、对比节、章节标签、付费清单、免责、安装括号等
指针重复「细节去文档站」类约 7 处
产品词「16 个色槽」「第 1～4、6～8 节」「反解」等首现无解释
第一人称「交过学费 / 每天在用 / 不是演示品」连读像自我评价

来源：案例记录「方法落地 · 先诊断」。

03 / 改法中档 · 保真

合并决策句，补人话，删不可验证声明。

改前倾向 负担
分档与免责全文多处完整重复；口号位占开头；产品词当读者已懂；品质声明三连。
改后原则 落点
决策句只留开头一次，其余一行指针；开头改定义句；产品词首现半句人话；保留可验证动作，删「不是演示品」。
事实账

约 15 项；数字与付费边界未动。

档位

中档：打散均匀、拆抽象，不重排论证骨架。

不交

不编经历；不把轻销售决策句抹掉。

04 / 盲读无上下文

写稿自评不算；子 Agent 读出 5 条。

第二遍啰嗦

分档信息散落，盲读读者明确报告读到第二遍觉得啰嗦。

先卡产品词

卡住顺序是色槽、节名，不是 WCAG 等通用词。

像简历评价

品质声明连读像自我评价；改为可验证动作优先。

定义句过关

开头换成定义对象后，复述测试通过。

发现全部回写改法；未跑则须在交付说明写「未盲读」。

05 / 对账当次摘要

改了多少处，数字动没动。

事实账15 项，改后逐条在
脚本文章模式跑 sawdust / rhythm 等；分档合并后不再作为主要问题
change_list约 57 处差异；数字变动 2 处均有申报理由
盲读5 条可落地发现 → 已改

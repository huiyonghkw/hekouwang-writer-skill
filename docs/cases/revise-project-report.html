修订流程四步

先锁住不能动的事实，再改点名的问题。

修订模式的第一动作不是改句子，而是重读当前版本，确认哪些内容属于用户资产：项目名称、已经确认的数字、责任归属、时间范围，以及明确要求不要触碰的段落。这些内容先进入保护清单，后面的每一处改动都不能顺手带走它们。

第二步才是定位问题。以本页为例，“基本完成”没有说明完成到哪一步，“尽快处理”没有交代由谁在什么条件下处理。改法不是把模糊词换成更漂亮的模糊词，而是回到材料，只写材料支持的状态：接口联调已经完成，异常重试仍待验证。材料没有给出的完成比例和批准日期，继续留在待确认区，不替用户补一个看起来合理的值。

第三步是对账。每一处修改都要能对应回原句，说明删了什么、补了什么、依据在哪里。实际任务中由 change_list.py 列出改动和数字变化，再人工确认没有范围外改动。第四步是边界复核：检查改后文本是否偷偷增强了结论，是否把“可能”写成“已经”，是否把责任从具体角色转移到了模糊的“团队”。

这套顺序也解释了为什么不能整篇重写。整篇重写看起来更整齐，却很难证明哪些事实被保留、哪些被替换。修订模式宁愿留下原本不够漂亮但准确的句子，也不拿流畅度交换事实。

本页使用占位项目素材，未运行脚本，也不代表任何真实项目结论。它展示的是修订顺序和判断标准。

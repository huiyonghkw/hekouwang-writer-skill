从零散素材
写出能照着做的说明

这个案例展示 WRITE 五步如何把流程排成动作顺序，同时把没有证据的时限、地点和逾期处理保留为待确认项。

案例：流程演示材料：占位素材脚本：尚未执行
输入素材

已确认四个动作

提交申请 → 负责人确认 → 领取设备 → 归还并登记。

不能猜的内容

三个待确认项

审批时限、领取地点、逾期处理方式。缺材料时不拿常识填空。

输出片段

申请与领取

  1. 提交设备借用申请，并填写设备名称、使用人和计划归还日期。
  2. 等负责人确认后再领取设备。
  3. 领取时核对设备及配件，并记录当前状态。
待确认：申请入口、审批时限、领取地点需由设备管理员补充。
方法

先锁读者和用途

读者是第一次参加流程的同事，目的不是介绍制度，而是让他知道下一步按什么顺序办。

验证状态

尚未执行

这是占位流程演示。真实材料齐备后，再运行对应检查器，不报告虚构的通过结果。

文档模式WRITE 五步

让人照着做，而不是读完觉得有道理。

操作说明的第一读者是第一次办这件事的人，不是制度制定者。所以开头不介绍背景和意义，先写清楚这份说明解决哪一步、读完应该能完成什么。读者、用途和边界定下来，后面的取舍才有依据。

第二步排结构。动作类文档按办理顺序组织，一步一个动作，条件和结果写在同一段里。不要把“申请条件”“所需材料”“办理流程”拆成互不照应的三节，让读者来回翻。第三步清点素材：已确认的动作直接写，缺失的时限、地点、联系人和逾期处理集中列在待确认区，不用“一般”“通常”这类常识填空。

第四步才是措辞。动作句用动词开头，主语明确；一次只写一个动作；条件放在动作之前。“等负责人确认后再领取设备”比“领取设备需经负责人确认”更容易照着执行。涉及核对配件的步骤，要写清核对什么、在哪里记录，而不是笼统地说“检查设备状态”。

第五步验证。让没有上下文的人按文档走一遍，记录他在哪一步停下来提问；那个停顿位置通常就是说明缺信息的地方。结构检查可以交给脚本，但“这一步是否真的能执行”只能由试走的人回答。

本页是占位流程演示：四个动作来自示例素材，审批时限、领取地点和逾期处理仍待补充；未运行脚本，也不代表真实制度。
